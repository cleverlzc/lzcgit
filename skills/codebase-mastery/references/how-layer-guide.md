# How 层构建指南

构建"怎么实现"层时，按以下维度逐个分析，确保不遗漏关键机制。

## 分析维度清单

| 维度 | 追问 | 典型产出 |
|-----|------|---------|
| 数据存储 | 数据存在哪？内存/磁盘/分布式？ | 存储模型、分配策略 |
| 数据传输 | 数据怎么搬？零拷贝？序列化？ | 传输协议、拷贝机制 |
| 数据路由 | 请求怎么找到数据？本地/远端？ | 路由算法、分片策略 |
| 并发模型 | 怎么处理高并发？线程/协程/池？ | 线程模型、分区策略 |
| 索引结构 | 怎么快速找到数据？B树/Hash？ | 索引类型、读写路径 |
| 一致性 | 怎么保证数据一致？同步/异步？ | 复制模型、一致性协议 |
| 容错恢复 | 挂了怎么办？降级/重试/迁移？ | 故障检测、恢复流程 |
| 硬件加速 | 有没有专用硬件？GPU/NPU/RDMA？ | 加速路径、适配策略 |
| 安全隔离 | 怎么隔离租户？配额/权限？ | 隔离模型、RBAC |
| 部署形态 | 怎么部署？容器/物理机/混合？ | 部署架构、配置管理 |

## 数据流追踪模板

对每个核心场景，画出完整调用链：

```
入口(API/SDK)
  │
  ▼
协议层(序列化/反序列化)
  │
  ▼
路由层(本地/远端判断)
  │
  ├── 本地路径 → 存储层(索引+内存) → 返回
  │
  └── 远端路径 → 传输层(网络协议) → 远端存储层 → 返回
```

追踪要点：
- 标注每一步的函数名和文件位置
- 标注数据在每一步的格式变化
- 标注同步/异步边界
- 标注错误处理路径

## 关键机制提炼模板

核心实现: ...
