# Why 层构建指南

构建"为什么这样设计"层时，对每个关键设计决策做对比分析。

## 分析框架

对每个设计决策，回答三个问题：

1. **为什么选这个方案？** — 它解决了什么问题
2. **为什么不选替代方案？** — 替代方案的缺陷
3. **这个方案的代价是什么？** — 它引入了什么新问题

## 对比分析模板

```
设计决策: [决策名称]

| 方案 | 优势 | 劣势 |
|-----|------|------|
| 方案A (替代) | ... | ... |
| 方案B (选中) | ... | ... |

决策理由: ...
代价与应对: ...
```

## 常见设计决策分类

| 类别 | 典型决策 | 常见替代方案 |
|-----|---------|------------|
| 架构风格 | 分离式/微服务/单体 | 各自对立面 |
| 并发模型 | 协程/线程/线程池 | 各自对立面 |
| 存储引擎 | B+Tree/LSM/Hash | 各自对立面 |
| 通信方式 | 共享内存/RPC/消息队列 | 各自对立面 |
| 一致性模型 | 强一致/最终一致 | 各自对立面 |
| 部署形态 | 融合/分离 | 各自对立面 |
| 扩展策略 | 分片/复制/缓存 | 各自对立面 |

## 追问技巧

对每个设计决策追问：

- **如果不这样做会怎样？** — 反向验证必要性
- **在什么条件下这个决策会失效？** — 识别边界
- **有没有更简单的方案？** — 验证是否过度设计
- **业界同类系统怎么做的？** — 对比验证合理性

## 设计哲学提炼

所有设计决策通常围绕少数几个核心权衡，提炼出来形成设计哲学：

```
用 X 换 Y，用 Z 补 W
```

例如：用空间换共享，用零拷贝补延迟。
